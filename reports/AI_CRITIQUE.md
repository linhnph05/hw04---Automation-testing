# AI Critique

The AI helped me read three features and suggest many positive, negative, edge, and security tests. However, the first scripts were not ready to submit. The AI used CommonJS even though the project used ES modules. It also copied unsafe behavior from the current application. For example, normal coupon requests sent `user_id` from the client, but the server should get the user from the JWT token. One guest test searched the whole page for “Đăng nhập” and matched the Login link in the menu. The AI also treated a deleted coupon as an inactive coupon, but these are different cases.

The AI missed these problems because it followed common Playwright examples and the current API behavior. It did not fully check the project settings or the limits of the test setup. It sometimes put two requirements in one test to reduce setup work. This made failures harder to understand. For access-control tests, it first checked only HTTP status codes. It did not check whether blocked data was still saved.

I learned that AI works best as part of a review loop. I should ask it to read the source, design tests, and write code in separate steps. I should run a small group of tests before asking for more code. I must compare each assertion with the written requirement, check selectors for false matches, and check saved data after a security failure. AI can save time and suggest useful cases, but I must review the code, run the tests, and take responsibility for the final work.
